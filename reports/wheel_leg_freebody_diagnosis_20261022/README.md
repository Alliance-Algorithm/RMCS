# 自起失败归因与 Isaac Sim 6.0 自由机身验证

本轮按“先分析，再仿真”执行。只增加离线诊断、仿真适配器和报告内的单条件消融，没有修改控制器、YAML、模型或启动实车。当前控制源文件与上轮冻结报告的哈希一致，见 `provenance.json`。工作期间仓库发生了其他提交和构建工具修改，不属于本轮诊断改动。

## 已确认的结论

新 CSV 共 54,179 行、235 列，记录 13 次进入 FOLD。整份 CSV 中控制器 `state=3` 和原生恢复 `native_phase=9` 均未出现。因此这些尝试尚未进入 RL 控制。`rl_bridge valid=1` 只说明推理结果可用，不代表执行器已交给策略。

13 次尝试中，5 次记录原生错误 1，4 次记录原生错误 2，另外 4 次从外层控制器退出、原生错误未锁存。后 4 次的具体外层触发点不能仅凭这份 CSV 确认。不能将它们一概归为同一个目标检查错误。

### 1. 最后两次失能：目标就绪条件被混入“反馈有效”条件

CSV 索引 18995 和 19349 的起始膝角、轮轴前后偏差与用户最新两段日志吻合。CSV 为约 200 Hz，日志和控制器为 1 kHz，因此可能采不到仅持续 1 ms 的 PREPARE。

| 项目 | 第一次，索引 19045 | 第二次，首个失能采样 19398 |
| --- | ---: | ---: |
| IMU 横滚 | 17.263° | 17.587° |
| 实测 FK 膝角 | 54.689° / 52.849° | 53.912° / 51.949° |
| 实测轮轴相对 COM 的前后偏差 | +213.875 / -187.229 mm | +211.093 / -182.510 mm |
| 原生恢复错误 | 1 | 1 |
| 原始 C++ 目标计算返回 | invalid | invalid |
| 单条件消融得到的目标膝角 | 40.5° / 40.5° | 40.5° / 40.5° |
| 目标前后误差 | 小于 0.000001 mm | 小于 0.000001 mm |
| 目标左轮沿重力低于 COM 的距离 | **39.858 mm** | **38.528 mm** |

`RecoveryTuckController::measure()` 将“两个轮轴沿重力低于 COM 超过 40 mm”计入 `ready`。`update()` 在目标 IK 已有有限解、膝角正确且前后误差接近零时，仍因为 `solved.ready=false` 把整个更新改成 `valid=false`。随后 FSM 的输入校验立刻触发原生错误 1。这里不是电机或 IMU 数据过期，也不是这两次日志中的相对铰链越限。

特别是第一次，只差约 **0.142 mm** 的目标投影距离，就触发了整段失能。此处应区分数学解有效、执行中实测到位、交接姿态是否合适，而不是把三者都作为“反馈无效”。

定位：

- `rmcs_ws/src/rmcs_core/src/controller/chassis/wheel_leg/recovery_tuck_controller.cpp`，`measure()` 的 `below` 与 `update()` 的 `!solved.ready`。
- `rmcs_ws/src/rmcs_core/src/controller/chassis/wheel_leg/joint_reference_recovery_controller.cpp`，`update()` 对 `tuck_valid` 的强制要求。
- `controller_recovery.cpp` 将原生错误锁存为 InvalidFeedback。日志 `failure=0` 则来自 `log_fault_()` 打印空的可选 reason，未打印已经锁存的原生错误；CSV 中实际记录为 1。日志需要区分该错误来源。

### 2. 正常站姿也可能被安排一整圈转位

当前 SELECT 强制进入 FOLD，FOLD 保持的是同侧两根主动轴角度的均值，并非由闭链 FK 定义的轮轴方位。缩腿之后，目标若在指定旋向的反面，即使只差一点，`directed_tuck_goal_()` 也会选择接近整圈的转位。

自由机身仿真中，初始轮轴已经对齐 COM、站高 305 mm、机身仅倾斜 0.261°，缩腿后 PREPARE 的剩余量重新跳到约 **6.23 rad**。交接前腿对的参考共转了约 **371°**，机身最大倾斜 **33.659°**，直到 **2.264 s** 才发出 RL 所有权事件。50° 膝角的正常对齐站姿也出现同样问题，2.215 s 才交接。

此外目标依据实时重力求解：`g.cross(UnitY)` 定义前后方向，目标随 IMU 改变。它并非一个固定在车体坐标系中的图示腿姿。机身被脚本带动后，转位终点还会继续移动。

这证实了正常姿态下不必要的大幅动作和明显失姿。**本轮正常站姿仿真未复现完整 180° 翻车**，不能将翻车全部归因于某一条代码。硬件 CSV 中，一次从约 10.7° 起始的尝试在脚本阶段已达到 165.9°；另一次从约 5.8° 起始的尝试达到 110° 以上，说明失姿确实发生在 RL 接管之前。

### 3. 倒扣起始姿态被旧的直立路线退出规则提前终止

新轨迹模式对所有可计算的起始姿态都强制设置 `route=Upright`，包括倒扣。进入 PREPARE 后仍保留旧规则：未推断到支撑且倾角超过 70° 持续 0.15 s，Upright 路线直接失败，原生错误为 2。

CSV 中索引 6409 的倒扣尝试：0.250 s 左右进入 PREPARE，约 0.400 s 退出。自由机身仿真同一起始几何：0.243 s 进入 PREPARE，**0.393 s** 以原生错误 2 退出，机身仍倾斜约 158.7°。这条规则尚未给整段固定方向转位留够时间。

### 4. “轨迹走完”并不等于“实测已经缩到 40°”

FOLD 转 PREPARE 的条件主要是参考剩余量小于 0.005 rad、四轴最大跟踪误差小于 0.20 rad。两个轴可向相反方向各差近 0.20 rad，实际闭链膝角就仍可达到约 55°。

用户日志中 FOLD 结束时膝角为 55.10° / 53.09°，腿速度约 5.9–6.1 rad/s，反馈力矩约 21–29 Nm，表明机械系统仍在快速追踪。3 倍参考速度没有消除执行滞后。此时立刻切入转位会把尚未完成的缩腿和转腿叠加。

FOLD 不启用轮子俯仰平衡；PREPARE 的轮子平衡还受条件支撑和 55° 倾角窗口约束，快速缩腿、卸载时经常退出。仿真中正常站姿条件支撑在快速缩腿时也变为 false。这是机身姿态会被腿部反力带动的另一项机制，不能靠固定机身试验验证。

## Isaac Sim 验证

环境为 Isaac Sim **6.0.0.1**，IsaacLab 3.0 beta2，CPU PhysX，1 ms 物理与控制步长。使用同一份 107° 资产及六个真实闭链约束，模型 SHA256 为 `0ac82045ab584f20091538aa782d93ea545382dc701faca1f8ae92aeb7cd1997`。机身六自由度完全释放，有地面接触。只在初始化时写一次位姿和关节状态。

适配器直接编译当前 `RecoveryTuckController`、`JointReferenceRecoveryController`、`ClosedChainSupportObserver`；每步从物理机身姿态、角速度和线速度差分生成重力、陀螺仪和比力反馈。没有以真实接触替代原生支撑观测器。

| 初始工况 | 首次脚本终点 | 时间 | 终点前最大机身倾角 |
| --- | --- | ---: | ---: |
| 轮轴对齐 COM，膝角 50° | RL 所有权事件 | 2.215 s | 33.596° |
| 已对齐、膝角 40.5° | RL 所有权事件 | 0.021 s | 0.282° |
| 对齐腿位，横滚 18° | 原生错误 1 | 0 s | 18.000° |
| 正常 305 mm 站姿 | RL 所有权事件 | 2.264 s | 33.659° |
| CSV 索引 3577，首次近直立起始 | RL 所有权事件 | 1.928 s | 29.415° |
| CSV 索引 6409，倒扣 | 原生错误 2 | 0.393 s | 179.837°（起始已倒扣） |

上表只表示脚本是否发出交接事件，**不是 RL 接稳通过率**。第一次脚本失败或发出交接事件后，适配器立即将六个电机输出归零；后续被动运动只供检查惯性和接触，图中的仿真曲线只画终点之前。

基线七工况闭链最大间隙不超过约 0.19 mm（含终点后的被动段），终点前最大电机力矩 40 Nm。资产是刚性机械止挡；源 CSV 索引 18995 的右膝为 107.0038°，略超 107° 止挡，因此完整物理重放采用第二次的索引 19349，没有通过裁剪该角度来伪造重放。

### 单条件消融

只在报告内复制源文件，将 `if (!solved.valid || !solved.ready)` 改为 `if (!solved.valid)`，其余轨迹、旋向、速度和物理参数不变：

| 工况 | 原始代码 | 单条件消融 |
| --- | --- | --- |
| CSV 最后一次异向腿位 | 0.226 s 原生错误 1 | 1.968 s 发出 RL 所有权事件 |
| 横滚 18° | 起始立即原生错误 1 | 2.215 s 发出 RL 所有权事件 |

这支持“就绪条件误作解无效”是该退出机制的因果解释。消融仍有多余转圈和姿态摆动，不是一份可发布的完整修复，也未验证策略接稳。

## 下一步应改的行为

1. 分开目标解有效、实测几何到位、交接条件；有效解但尚未就绪时继续执行，不以无效反馈立即失能。
2. 缩腿保向以真实闭链轮轴方位定义。轮轴已在车体 COM 下方时，完成缩腿就交接，避免为了固定旋向额外整圈。确实需要转位的腿位继续保持用户指定的固定旋向。
3. 明确终点使用车体坐标还是重力坐标，避免脚本反力引起 IMU 改变后不断追逐移动终点。将图示固定腿姿与机身自起所需动作分清。
4. 不将倒扣、侧倒强制标记为旧 Upright 路线。脚本的允许时间与实际选定路径对应，保留真实传感器异常、机械边界和遥控器复位。
5. “先缩腿”依据实际膝角和轮轴几何完成，之后直接交接；不增加慢伸腿。轮子应在缩腿和转位时参与机身控制。

修改这些行为后，需要重复自由机身工况，并接入真实策略验证接管后的稳定性。当前结果没有证明完整 180° 翻车的全部实车成因，也没有证明 RL 策略能从这些交接状态接稳。

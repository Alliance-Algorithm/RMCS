# 前言

在你开始继续走传统路线前，如果你有成型的路线和基础，那么你可以略过这个仓库，因为它没能真的sim2real，如果没有，也许这个仓库会帮助你。
	
具体的控制链和代码都有md讲我也不过多赘述。
	
关于编译，build-rmcs-sim是带有mujoco参数的编译，launch-rmcs-sim是启动仿真链路。build-rmcs是实机代码，也就是说你至少要编译两次。
	
然后是实机和仿真的gap，传统路线使用的是mujoco做仿真(当然你可以做isaacsim，如果你是ubuntu的话我极力推荐isaacsim)，mujoco与实机最大的gap是摩擦，仿真环境对于摩擦的处理非常粗糙，如果你要做轮对于整机的平衡（你肯定要做），一定要做好摩擦方面的鲁棒，我这方面其实做的不好，是靠轮力矩输出上限进行的限幅，你需要更好的方式来缩小sim2real的gap。

另一个不算gap但是很复杂的是urdf和实机的标定，你拿到的urdf在电机符号，零点和解算上与真机有差别，你需要一个标定yaml来标定所有的差异并且验证，这个位于/workspaces/RMCS/rmcs_ws/src/rmcs_bringup/config/wheel-leg-infantry-stand.yaml。
我留下了标定模式来帮助你标定轮和腿的六个电机并且进行验证，但让你用之前最好检查一遍，我不保证在以后的实机上还能用，尤其是机械参数与canID。

关于辨识，没有很好的办法进行辨识（至少我没能找到），也许你可以等rl侧先出一份能控制的代码（老登一般很快）然后拿来辨识，如果你的目的是一个简单的能站立的程序，那么你需要的只是固定位姿下的数据。但如果你想要真的控好这个轮腿，那么你需要的是一个能搭建整机耦合的数学模型。

# 关于控制算法

仓库里有LQR,ADRC，你找找其他地方还会有SMC,现在前沿的经典控制理论算法基本都在这了，你所需要的所有模块都能在这找到，但是你使用的时候要注意算法本身的特性，比如ADRC不擅长处理高频的控制链路，LQR不擅长处理真实与模型差距大的控制链路，SMC我不太了解，不过它的鲁棒性是最强的（but，what cost）。很多地方你可以组合起来用，比如ADRC的ESO，你可以把它单独摘出来当作一个估计器并在别的地方接入链路，比如用来实时修正LQR的模型，毕竟场上你的数学模型是会变化的。

# 终极愿景

妄言传统路线的上限有些飘忽了，但是轮腿作为自由度最多，受控量最广的机器人，它的上限是这个赛事中最高的。从腿和轮开始，轮是唯一的外力作用单位，是整个轮腿机器人中最重要的一环，你的整车平衡，姿态变化的根源是轮，腿是决定你轮作用大小的单元，比如平衡，短腿长时你做平衡需要的力矩和伸长时需要的力矩是不同的，你可以灵活的应用这个特性对你的轮力矩进行缩放以便你变换姿态。如果你用的是LQR的话，你需要一个矩阵，用来描述腿长和腿角不同时轮对于整车位姿的LQR系数（如果能构建出数学模型肯定最好，但那很难），你可以在仿真中扫出这个系数上车用（但是一般不准）。

如果你有充足的时间，其实可以建立一个基于物理的数学模型，将轮/髋两个同轴电机对外的作用写为函数，接入的惯量/质心等留作形参，这样可以得到一个很精准的数学模型，但也相当吃你的实车模型精度。

我猜你一定会使用AI来做这些，这些细节AI比人强，交给AI就好，当然需要你去实机上采集数据。

## 配置与控制交接

新入口：
[`wheel-leg-infantry-wheelbipe-recovery.yaml`](../../rmcs_ws/src/rmcs_bringup/config/wheel-leg-infantry-wheelbipe-recovery.yaml)。
模型为 `models/wheel_leg/wheelbipe_v202_8500_50hz.onnx`，旁边的 `.deployment.json`
记录 checkpoint、实际更新数、ONNX SHA-256 和数值误差。原有两份早期快照配置保留各自出处。

脚本核心及几何来自 RMCS `2e883162762f0d658a7cc2e066ccbd00698c1d01` 的传统 v2.0.2
实现，机械模型及气簧 SHA 与当前 WheelBipe 相同。它作为 `WheelLegController` 内的
已有求解器使用，不增加并行电机命令所有者或额外插件。

规范模型 SHA 以 `8a9d7595…` 开头，Isaac 物理版本为 `388dbdc6…`：逐字段比较确认
唯一差异是两个云台关节在物理版本固定为零并移除其运动限位；其余机械数据完全相同，
本次物理初态的云台坐标均为零。历史侧卧/倒置姿态的云台 yaw 有非零值，本次明确投影到
固定零位，不能称为原姿态逐状态复现。以完整碰撞网格顶点和圆柱边界重算后，站立、趴地、
左侧、右侧、倒置的初始最小离地间隙依次为 0、8、2、2、2.203 mm，未在该几何检查中穿地。
这不证明被动静置或动态接触；两种模型文件身份与投影回执分别记录。

控制链是 `PREPARE(2) -> RECOVER(4) -> RL(3)`：

- PREPARE 等待正常驱动清错/使能握手，力矩为零。
- RECOVER 在 200 Hz 推进脚本，使用测量的编码器、IMU、轮速、气簧抵消和支撑补偿。
  该阶段策略桥失能，不能让站立策略直接接管倒地姿态。
- 核心 Complete 要求稳定保持至少 0.5 秒；额外交接条件包括重力 z<−0.9903、
  横滚/俯仰角速度合量<0.35 rad/s、腿速<0.6 rad/s、轮速<2 rad/s，
  以及绕组一致的策略名义腿角误差<0.25 rad。
- 满足捕获后才启用推理；等待首个新鲜动作期间继续脚本捕获力矩。
  首动作到达后立即切换 60/2 策略反馈 PD，气簧抵消和脚本积分退出，动作历史从零开始。
  初次观测指令为零速/名义高度，交接后再跟随遥控参考。
- 超时、脚本故障、反馈过期、捕获丢失或推理故障会清零并锁定故障。
  双 DOWN 显式复位清除轨迹、积分、推理历史及故障；不会因恢复传感器就自动重新使能。

两个阶段共用关节软限位投影、40/4.5 N·m 上限、标定 Jacobian 及电机映射。
脚本保留实际腿速 3.14 rad/s 故障保护及最长 30 秒预算，没有为了让测试通过放宽保护。
此配置仅处理启动阶段的脚本自起，不能将策略运动中跌倒后的恢复计为已实现。

调度为 1 kHz executor / 200 Hz 反馈控制 / 50 Hz 策略。新诊断接口为
`/wheel_leg/rl/recovery/{phase,fault,capture_ready}`，已接入记录和转发。
策略阶段仍限制 ±0.5 m/s、±0.5 rad/s；本次没有为未经验证的更高速率扩大命令范围。

## 原生脚本检查的结果

使用同一冻结 WheelBipe 物理源、原生闭链、实体气簧、轮响应、腿摩擦，
通过 C ABI 执行同一个脚本核心，再交给保存的训练 actor。生产 executor/ONNX 桥另有集成测试。
每项仅一个 pose-bank 几何放置起点，不能视为被动静置后的实测初态。

| 起点 | 结果 | 交接时间 | 原生运行时间 |
| --- | --- | ---: | ---: |
| 站立 | 交接后维持至窗口末尾，无复位 | 5.64 s | 30.00 s |
| 低位趴地 | fault=5，轨迹未到达，无策略交接 | 无 | 5.62 s |
| 倒置 | fault=5，轨迹未到达，无策略交接 | 无 | 5.66 s |
| 左侧卧 | fault=5，轨迹未到达，无策略交接 | 无 | 5.58 s |
| 右侧卧 | fault=5，轨迹未到达，无策略交接 | 无 | 5.62 s |

站立起点后半窗平均速度 0.00683 m/s、高度 0.29925 m、倾角 0.282°。
表中锚点距离仅在策略观测边界测量，不能称为所有物理子步的最大值。
第一次诊断器沿用了站立任务的跌倒终止，倒地时被提前复位；修订后仅在脚本阶段
延后策略跌倒终止，保留 C++ 核心故障保护。三项完成后一次 Kit Mutex 断言导致诊断进程
退出（134）；左右侧卧在独立进程重新完成。所有原始失败及中间结果均保留。

**四个倒地起点都没有完成自起。后续需要修正、评测脚本轨迹，才能将其作为实用的倒地
启动流程；本次没有以绕过故障或直接放行站立策略代替完成自起。**


- 三包通过 `build-rmcs`；rmcs_core 11/11、rmcs_rl 2/2 CTest 通过。
- 新配置实际加载生产控制器、ONNX 桥、executor 与内存传感器；验证倒置不启用 actor、
  脚本超速故障、显式复位、新鲜动作交接、气簧补偿切换、动作历史与反馈过期清零。

  气簧 1201 组输入最大误差 3.040e−8 N·m。Prone 比较使用其冻结源码，不能用较旧的
  WheelBipe 源码副本替代 Prone v2 里程计实现。

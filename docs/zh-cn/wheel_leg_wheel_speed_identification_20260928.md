## 1. 代码中的真实控制链

- `hardware/wheel-leg.cpp`：M3508，CAN0，ID 1/2，两侧均由驱动层反向，减速比 `15.8`。反馈速度已经是轮输出轴 rad/s，策略目标不能再乘减速比。
- `hardware/device/dji_motor.hpp`：转子 RPM 除以 15.8 后转 rad/s；请求的轮轴 Nm 再换算成 C620 电流命令。当前代码使用 `Kt_motor=0.3/(3591/187)`，因此轮侧 API 的有效常数约为 `0.246834 Nm/A`，20 A 对应约 `4.93668 Nm`。这是代码换算值，尚非实测轴端力矩或持续热能力。
- `rmcs_rl/src/action.cpp`：正式 RL 轮侧是速度 **P**，`tau=0.2*(omega_ref-omega)`，并非髋膝位置 PD；当前正式入口仍按 200 Hz 计算并保持输出、1 kHz 发帧，策略 50 Hz。本次轮侧实验采用 **50 Hz 目标、1 kHz 速度环、1 kHz 原始记录**；正式训练和部署需要随后同合同迁移，不能仅靠录包配置宣称已完成迁移。
- 已被本轮替换的旧版 `start-wheels` 是低速探针：`Kp=0.25`、无 I/D、速度 0.6/1.2/2 rad/s、0.45 Nm 限幅。代码还硬编码速度不超过 3 rad/s、力矩不超过 0.5 Nm。这些是旧试探设置，不是 M3508 的性能边界。

官方 [M3508 手册](https://cdn-hz.robomaster.com/robomasters/public/document/RoboMaster%20M3508%20P19%20Brushless%20DC%20Gear%20Motor%20V1.0.pdf)给出标准 P19 总成参数；[C620 手册](https://cdn-hz.robomaster.com/robomasters/public/document/RoboMaster%20C620%20Brushless%20DC%20Motor%20Speed%20Controller%20V1.0.pdf)定义 CAN 电流控制与反馈。标准 P19 的输出轴规格不能直接冒充本车 15.8 总成的实测能力。电流码量程、软件限幅、持续力矩和转速相关可用力矩分别归档。

## 2. 旧实验的缺口（本次已在程序中修正 1/2/3/5）

1. 只有五次多项式斜坡、保持和反向验证，没有速度阶跃、分频段激励，也缺少充分的低速起转采样。
2. 当前顺序是“速度环刹到零 → 零电流”，这种 coast 段接近静止，无法有效估计转动惯量与摩擦。应从稳定非零转速直接切零电流。
3. 当前两轮总是同目标，缺少单轮、共模和差模对照，无法充分检查通道映射和共用供电影响。
4. 旧轮图要求四个腿电机失能。车体被支撑时，腿仍可能被轮驱动反力带动；不能把这等同于轮轴支架刚性固定。
5. `start-wheels` 已检查文件/动态库哈希和 recorder 订阅，但运行时参数比对目前只覆盖髋膝控制器；新版轮入口要补速度环增益、限幅、目标频率、序列和采样状态回读。

## 3. 架空条件和实验顺序

先左轮、再右轮，最后双轮复核。保持车体支撑、轮不接触地面。**本轮四个 DM 全失能，腿总成悬空，被动自由度没有锁定**；未给腿添加未验证的保持控制。每个样本同时保存四轴 q/dq/估计力矩与 IMU。只有支架运动可以忽略、转速已稳定的窗口才用于简单摩擦平台拟合；运动明显的动态段必须保留完整耦合结构回放，或明确拒绝按固定轮轴单惯量拟合。

以后若机械固定腿姿态，可用单轮惯量模型；若由已冻结的髋膝 PD 保持姿态，需同步记录其目标、实际运动和控制力矩，并在回放里保留这些自由度。车体有支撑不等于轮轴支架固定。

轮自身转轴上的重力项主要取决于轮的偏心和安装方向，不能照搬髋膝的重力矩；腿总成的重力、气簧和轮驱动反力仍存在。若观测到轮角周期性的阻力，再增加偏心/周期项，不预先让轮摩擦吸收所有腿部运动。

## 4. 每侧预设序列

下表给出目标覆盖；本次物化轨迹见表后的执行参数。设计值不是已验证能力，所有正反向成对、切换段和拟合段分别标记。

| 段 | 激励 | 用途 |
|---|---|---|
| 零输入与小幅正反转 | 零电流静置；约 ±0.2、±0.5、±1 rad/s | 检查符号、死区、起转与停止附近行为 |
| 多速度平台 | ±2、±5、±10、±20、±30 rad/s，平台约 3 s | 在实际稳定后的窗口拟合电流—速度关系；30 rad/s 不是最终最高速度 |
| 多级阶跃 | 0↔±2、0↔±5、5↔10、10↔20、20↔30；包含同向和反向变化 | 上升时间、超调、稳态误差、限流后的恢复；重复至少两次 |
| 慢三角与快斜坡 | 低速跨零三角；较高偏置速度上的往返斜坡 | 分离近零摩擦、粘滞阻力与惯性负载 |
| 非零转速零电流滑行 | 在 ±5、±10、±20 rad/s 稳定后直接令电流为零，直到充分减速或本段超时 | 惯量/摩擦的独立约束；这是通电零电流，不是 ESC 断电 |
| 带偏置扫频 | 偏置 ±5、±15 rad/s；0.1–2 Hz 大幅、2–8 Hz 小幅 | 50 Hz 目标下的实际闭环幅相；保留跨零与不跨零两类数据 |
| 可选高速诊断 | 仅在需要且实际反馈带宽支持时，1 kHz 独立目标发生器下小幅 8–30 Hz | 区分目标保持与执行器响应；明确标为诊断，不能伪称 50 Hz 策略同链验证 |
| 留出轨迹 | 不同频率/相位的多正弦及未参与整定的阶跃组合 | 冻结增益后的独立检验；若据此继续调参，就另录验收包 |

本次执行值：低速 ±0.2/0.5/1，平台 ±2/5/10/20/30 rad/s，平台 2 s、进出斜坡 1 s；阶跃保持 1 s，重复 2 次；±5/10/20 rad/s 平台后直接零电流滑行 4 s。扫频偏置为 0/±10 rad/s，0.2–2 Hz 幅值为 3/5/5 rad/s，2–8 Hz 幅值为 0.4/0.8/0.8 rad/s，各 12 s；两端 0.5 s 平滑衔接。未开启独立 1 kHz 高频目标实验。

留出多正弦频率 0.37/1.13/2.71/5.17 Hz、相位 0/0.7/1.9/2.8；单轮偏置 ±7、总幅值上界 5 rad/s。双轮复核包含同 API 符号与反 API 符号的阶跃、扫频、多正弦。未被选择的轮始终零电流，不用速度环刹住它。

首包命令电流上限 20 A、轮轴 API 上限 4.936675 Nm。参考对照包改为 18.230894 A / 4.5 Nm，驱动硬件发布的满量程仍为 20 A / 4.936675 Nm，启动时分别核验软件限幅与硬件满量程。它们不是实测持续轴端力矩。双下立即归零电流，M3508/C620 不发送 DM 的 MIT 失能帧；四个 DM 继续保持失能。

默认 50 Hz 零阶保持目标必须在 20 ms 边界更新；速度环仍每 1 ms 用新反馈计算。高频激励不盲目维持恒幅：正弦峰值加速度为 `2*pi*f*A`，应根据实测惯量、阻力和电流余量缩放幅值。高幅限流片段保留用于非线性/饱和验证，线性频响拟合使用未持续限流的片段。

双侧复核采用相同机械前进方向的共模以及相反机械方向的差模，也保留一轮动、另一轮零电流的片段。机械方向先通过轴映射确认，不能仅凭两个 API 数值同号命名“共模”。

## 5. 整定和物理参数辨识分开评价

首包 Kp=0.2 是本地 RL 链基线；0.25 仅为旧探针。下一包从上游参考的 0.6/0/0、±4.5 Nm 起步，同一条 630 s 轨迹、同一 50 Hz/1 kHz 时序，比较低速起转、稳态误差、阶跃超调、停止附近抖动、扫频跟踪与电流占用。首包峰值仅 2.126 Nm，因此其更高软件限幅没有介入；新包可能在阶跃限流。限流段与未限流段分别比较，不能把整条曲线的变化全部归因于 P 增益。只有实测对照通过才选择 0.6，不能先假定参考参数对本车最优。增加 PI 或摩擦前馈要有持续稳态误差证据，并同步实现积分限幅/抗饱和、失能清零及仿真同算法，不能只在实机上把 I 打开。

物理模型首先使用轮轴口径：

`J_eq*domega/dt = tau_act - tau_c*sign(omega) - b*omega - tau_external`。

先用稳定平台估计正反向阻力，用低速起转单独约束静摩擦，再用加減速与零电流滑行约束惯量。单独一条滑行曲线主要约束 `tau_c/J_eq`、`b/J_eq`，不能宣称同时唯一辨识出惯量、力矩常数和摩擦。无轴端扭矩传感器时固定可信的换算基准，报告有效参数与不可辨识项。

执行器延迟/响应按未饱和动态片段和留出轨迹检验；反馈速度滤波、CAN/USB 的主机时间戳和电流报告延迟分别处理。电流反馈换算的 Nm 是估计量，不是负载传感器真值；亚毫秒 USB 通信也不等于整个轮速闭环响应。

最终需要同时通过：速度曲线的自由前向回放、留出阶跃的超调/稳定时间、留出扫频的幅相、起停/反向行为，以及两侧差异检查。冻结速度环后重新录正式包，再把已验证的摩擦、阻尼、惯量/armature 和执行器响应接入训练。

## 6. MCAP 必须保存的内容

继续采用 `/wheel_leg/identification/sample` 的原始 1 kHz MCAP，Foxglove 只负责显示与回放，不拿 50/100 Hz value broadcaster 代替原始数据。

- 目标轮速、输出轮速/轮角、两侧符号和减速比；控制 tick、单调时钟、目标更新时刻/持有规则。
- 限幅前力矩、控制器请求、量化后的 CAN 电流命令与原始字节、实际电流反馈、饱和标记。
- 每轴反馈序号/接收时间、发帧提交时间、温度、模式、段号、拟合/验证标签、丢包计数。
- 同时保存髋膝 q/dq/力矩、IMU，检查轮轴支架运动；供电电压目前缺绑定时记录 NaN 并注明，不能填常数假装测量。
- profile、控制器/消息定义/动态库快照和哈希；增益、限流口径、50 Hz/1 kHz 时序均做运行时回读。

`DjiMotor` 已发布 `temperature_c`，recorder 可以绑定；现有消息中“轮温度不可用”的旧注释已经过时；本次保留原消息定义以兼容旧包解码，是否实际测到仍以本次反馈序号和字段值为准。

现有 recorder 字段已覆盖大部分原始量；若加入 PI，另增每轮积分状态及目标更新序号/时间戳，版本化消息并保留旧 bag 的原始定义。不能用新 CDR 布局直接解码旧包。

## 7. 进入训练的范围

架空包可校准空载轮传动摩擦、速度环和惯量/响应。轮胎地面摩擦、滚动阻力、负载下供电压降及车体耦合需要后续有负载验证，不能从架空包直接估计。训练仍输出轮轴 rad/s，但仿真必须保留匹配的速度环、力矩/转速包络和真实传动口径；不重复乘 15.8，也不继续混用旧的 11。

华南虎的轮侧摩擦/阻尼路线作为首选简化模型；只有留出数据证明不足才增加复杂度。网络结构保持不变。

## 1. 已有 RL 源码基线核对

腿部策略输出目标角。PC 以当前反馈计算：

`tau_request = 60 * (q_target - q_feedback) - 2 * dq_feedback`。

这是位置 PD，没有积分，没有 `Kd*dq_target` 轨迹速度前馈，也没有显式重力前馈。气簧和重力作为机械负载进入动力学；不能为了架空轨迹更贴目标，单独给辨识控制器加补偿，却不让训练/部署使用同一控制律。

|项目|RL 腿部路径|现有 04:01 bag|
|---|---|---|
|PC 控制器|位置 PD，Kp=60、Kd=2|位置 P=6，速度 P=10、I=50，带速度目标前馈|
|目标更新|策略 50 Hz，目标角保持 20 ms|连续预设轨迹每 1 ms 取样|
|控制力矩更新|200 Hz，保持 5 ms|1000 Hz|
|MIT 发送|1 kHz 重发保持的力矩，内部 Kp/Kd=0|1 kHz 纯力矩，内部 Kp/Kd=0|
|速度目标限幅|PD 公式没有中间速度目标|±4 rad/s|
|软件力矩上限|模型侧 ±40 Nm，随后还有映射/硬件限幅|±20 Nm|

依据：`rmcs_ws/src/rmcs_rl/src/action.cpp::compute_motor_torques_()`、`rl_controller.cpp::update()`、训练仓库 `src/wheeled_tasks/chassis/v5_control.py::motor_efforts()` 与 `env.py::step()`。本地物化诊断合同 `reports/v6_p0_diag_probe_20260928/train_control_verified/checkpoints/update_00000010/contract.json` 确认 60/2、物理步长 5 ms、策略步长 20 ms。这是对源码与归档合同的核对，不宣称当前机器人正在运行 RL。

RMCS 还包含目标角分支/机械限位、力矩投影、`J^T` 映射、硬件裁剪与 MIT 量化；开启恢复功能时还有附加包络/峰值预算。不能只复制一行 PD 公式就声称整个部署路径一致。当前普通 RL YAML 的标定矩阵和软限位仍为未就绪占位，不能把零矩阵拿来做辨识映射；新资产映射需单独核实。

轮子仍为速度 P 环，不能把四腿轴的 PD 结论推广到轮轴。

## 2. 要辨识的是 PD 后面的系统

Kp/Kd 是已知控制设计量；先固定它们及控制时钟，在完整总成中拟合以下数据支持的未知量：关节摩擦/阻尼、CAD 未覆盖的附加轴惯量、实际力矩响应/增益、反馈报告动态、可辨识的合成时延。电机轴端、输出端和主动关节坐标必须明确。

气簧静态曲线保持既有拟合，几何/质量/惯量先核对；车体按支架姿态固定，两电机带连杆、轮组、气簧共同运动，仿真开启重力并保留闭链自然耦合。不能拆成两个独立电机，也不能通过调整 PD 增益吸收机械模型误差。

若后续辨识证明 60/2 不适合，再把 **控制器重新设计** 单列实验，训练和部署同步更新。初始筛查不宣称替换 60/2；后续完整 PD 包证明差模激励不足，新增 120/3 带载采集候选见 §7。它仍未经实机对照证明更优，更不能将 1 kHz 结果直接用于 200 Hz RL。

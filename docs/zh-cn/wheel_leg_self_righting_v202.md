## 轨迹与控制链

`SelfRightingCore` 是无 ROS、无仿真依赖的 C++ 核心。Isaac Sim 通过 `self_righting_abi.cpp` 的 ABI v6 调用同一个核心，组件 `WheelLegSelfRightingController` 直接包含它，不复制一套 Python 控制律。

状态顺序为 **7 翻正 → 3 腿形归一化 → 2 将轮子放到身下 → 1 调至站立腿形 → 4 接稳 → 5 完成**。本来正向趴地时跳过 7；已经站立时可直接接稳。左右腿各自从测得的角度开始规划，支持同前、同后、左前右后、左后右前。腿的前后位置由完整闭链几何换算，不能把两个髋电机角度当作整个腿形。

阶段 3 的参数 `fold_knee_deg` 不要求一定收短。独立 Isaac 的 109° 长腿候选先保持支撑，再把轮转至身下，最后调至约 63.672° 站姿；105° 长腿正趴的四种前后组合出现了通过完整 25 s 行为窗口及有限 CAD 筛查的结果。倒扣也有完成窗口，但把失能沉降延长到 3 s 的同路线四组合全部未到位，不能据此宣称已经覆盖实际倒地端点。研究程序和逐项回执保存在独立 Isaac 工程中，默认 YAML 尚未选定或启用这些轨迹。

每段使用有加减速的关节空间速度轨迹，默认巡航 1.5 rad/s、参考加速度 3 rad/s²；分段交界从上一参考继续，避免用跟踪误差重新定位参考。位置外环生成有界的速度命令，电机端执行 `Kd * (v_cmd - v_actual) + feedforward`。前馈包含速度积分项、与 Isaac 相同的气弹簧补偿及可关闭的静态支撑补偿；支撑补偿只在起身/接稳时渐入，属于静态负载近似。

四轴顺序固定为 CAD 的 `L_joint1, LL_joint1, R_joint1, RR_joint1`，对应传统接口的左髋、左膝、右髋、右膝。膝角表覆盖 41–109°，站姿使用 v202 资产的约 63.672° 膝角、−0.656° 轮心轨道角。生成文件 `recovery_geometry_v202.hpp` 包含模型及气弹簧来源哈希，不适用于旧 V5/MuJoCo 模型。

翻正阶段支持有限次数的前后支撑，以及可配置的左右腿不同步轨迹。自起仅使用四个腿电机及轮电机，云台 yaw/pitch 均无主动输出。修正 Isaac 实验入口中的碰撞过滤及接触几何后，个别严格左右侧躺端点已有完成窗口和全窗有限 CAD 筛查；随机云台、倒扣与各腿组合仍未全面通过，不能将少数窗口当作传统自起功能通过。

`flip_program` 是最多 64 行、每行九个数的展平数组：`[下腿膝角, 上腿膝角, 下腿轨道角, 上腿轨道角, 轴巡航速度, 轴加速度, 到位后保持时间, 物理左轮速度, 物理右轮速度]`。角度为度、速度为 rad/s、加速度为 rad/s²、保持时间为秒；轮速目标绝对值最多 55 rad/s，轮力矩仍受 4.5 N·m 限制。行内腿角经闭链表换成四轴角度，四轴共用时间标度。

`flip_program_relative_to_side: true` 时，启用瞬间按重力方向确定下腿和上腿；该映射在一次轨迹内保持。设为 false 时，前两列及轨道角分别代表物理左腿、右腿。最后两列始终为物理左/右轮，不随上下腿映射交换。普通正趴初态跳过翻正程序，进入共同的收腿、支撑、起身流程。

`flip_fold_first` 可先在两腿各自实测轨道角上收至 `fold_knee_deg`，再进入第一行。每行必须到位并连续保持 40 ms 才开始保持计时；超过计划段时长 5 s 尚未到位则锁存故障 5。程序结束后仍未翻正时，进入有次数上限的普通翻正候选。`flip_capture_tilt_deg/gyro_rad_s/dwell_seconds` 共同控制翻正转入收腿的倾角、滚转/俯仰角速度和连续等待时间。`balance_wheel_speed_limit_rad_s` 与 `balance_distance_gain` 调整接稳轮速包络及轮里程反馈。上述都是研究参数，默认程序为空；实际可用轨迹尚未选定。

`flip_first_orbit_hold_mask` 默认为 0；位 1/2 分别表示第一行的第一/第二条程序腿保持本次启用时各自测得的轨道角，膝角仍执行该行目标。腿序遵循 `flip_program_relative_to_side`，取值为 0–3，只影响第一行。这样可先让一腿顶地，另一腿保持自身前/后位置；不会强制把本来在前的腿先移到后方。后续各行恢复绝对轨道角目标，复位后重新测量初态，配置保留。该选项不是全组合自起通过证明。

`flip_handoff_orbit_limit_deg` 默认为 0（关闭附加条件）；非零时，两腿实测轨道角去圈后都须落在车身下方指定角度范围内，才允许翻正转入收腿。这样可以继续执行伸腿旋转，避免车体刚翻正便从前伸位置收腿。`flip_balance_when_upright` 默认为 false；启用时，在翻正过程中倾角小于约 36.87° 就允许原有有界轮平衡，其输出优先于该行的固定轮速目标。两项仍是待原生行为验证的研究配置。

`flip_stall_dwell_seconds` 默认为 0，关闭停滞换步。非零范围为 0.05–2 s，仅对有限 Flip 程序中已结束参考运动却未到位的路点有效，不适用于前置收腿。四轴实际速度均须低于 0.6 rad/s、全轴车身角速度模低于 0.5 rad/s；最大轴角误差每减少 0.01 rad 就重启等待。超过等待窗无净进展时，清除跟踪积分和参考速度，仅把命令参考重建为实测编码器角度，尝试下一路点。物理状态、膝角包络、实际速度故障和完成门不变；它不代表接触检测或到位成功，也不保证此后的轨迹可行。

该研究选项通过 ABI v6 的新增 setter 与只读计数器暴露，原 20 输入/24 输出布局保持。计数写入 `/wheelleg/recovery/stalled_waypoints`、原生回执和 TensorBoard。弃用路点时允许命令位置重建，不能把此时的参考跳变解释为物理角度跳动；四轴实际速度和原生角增量仍独立检查。

双 DOWN 复位清除程序行号、上下腿映射、段计时、到位/保持计时、翻正切换等待、停滞进展基准/等待/计数、积分及参考，保留只读配置；再次启用从新的实测角度开始。

## 3.14 rad/s 的边界

速度命令限制在所设巡航速度内，巡航必须小于 3.14 rad/s。实测任一四腿轴速度超过 3.140001 rad/s，核心锁存故障并撤除主动输出；接近上限时先制动。电机前馈及估算总驱动力矩限制为 40 N·m。

DM 采用原 MIT 报文的 `Kp=0, Kd<=5` 速度伺服。保留原协议的速度量程 45 rad/s，另在命令编码前向内收一个量化码，保证有符号量化也不会把边界命令编码成超过 3.14 rad/s。不能通过改协议量程来伪造限速。

**命令限速不等于接触冲击下的实际转速保证。** 当前仿真成功案例还依赖 PhysX 的 2.8 rad/s 原生关节限速；取消该限速的对照出现实际超速。该理想限速在接触冲击下也出现过瞬时超限。DM 电机内部限速/制动、实际输出轴映射及报文反馈之间的动态力矩尚未通过台架或实车确认。软件检测发生在超速反馈之后，不能称作硬件速度保护已验证。

原生实验另外检查去圈后的输出角增量/物理步长，避免位置求解器移动关节但原生速度接近零时漏掉大幅位置修正；这与原生速度分别记录。有限步长角增量不是实车瞬时速度证明。

## 传统控制接入

- 自起输出位于 `/wheelleg/recovery/`，包含 `active/ready/phase/fault`、四轴参考角/参考速度、四轴速度伺服及前馈、两个轮力矩。
- `WheelLegDriveBridge` 仍是四个腿电机及轮力矩的唯一写入者。标定优先，自起其次，普通轨迹随后；自起故障时保持占用并撤力，不能回落到旧轨迹继续运动。
- 自起占用时，普通 `WheellegTrajectoryController` 清空自身参考与积分；站立状态机清空稳定计时，避免翻正阶段被当成已站稳。交接后普通轨迹从实际角度重新规划。
- 保留 DM 启动握手、遥控新鲜度、底层反馈新鲜度及原轮输出许可。等待 DM ready 时保持自起占用但输出为零，避免与普通轨迹争夺使能。
- 双开关 DOWN 清除全部自起参考、积分、故障、完成标志及使能状态。遥控失效时撤除输出。无遥控接口的仿真图需要显式 `/wheelleg/recovery/request`，不会因缺少遥控而自动运动。
- `handoff_enabled` 默认关闭。即使有限窗口达到完成门，也没有证据证明已能可靠接入整个 v202 传统站立/行驶控制。

故障码：1 非有限/非法反馈，2 反馈失效，3 实际超速，4 总时间到，5 段末角度未到达，6 接稳时再次倾倒，8 翻正尝试耗尽，9 DM 曾 ready 后掉线。故障只由明确复位清除；后续异常不覆盖首个核心故障原因。

## 配置和构建

`rmcs_bringup/config/wheel-leg-self-righting-v202.yaml` 是关闭状态的配置片段，不是可直接替代现有组件图的完整车辆配置。先从原图生成独立研究配置：

```bash
python3 .script/compose-wheelleg-recovery.py \
  --base rmcs_ws/src/rmcs_bringup/config/wheelleg_sim.yaml \
  --output /tmp/wheelleg-recovery-research.yaml
```

合成器检查状态估计、普通轨迹和唯一驱动桥，保留原组件，只追加关闭的自起组件；拒绝覆盖已有文件或重复自起组件。**这里的 `wheelleg_sim.yaml` 仍然是旧 MuJoCo/V5 仿真图，不能启用 v202 几何控制器用于该模型。** 此命令只验证图合成，不授权启动。

遵循仓库构建入口：

```bash
.script/build-rmcs --packages-up-to rmcs_core rmcs_bringup \
  --cmake-args -DBUILD_TESTING=ON
# 进入构建环境并加载安装空间后
cd rmcs_ws/build/rmcs_core
ctest --output-on-failure -R 'wheelleg_(self_righting_core|recovery_velocity_packet)'
```

## 启动辨识和录包

先保持遥控器双下。build、sync和wait-sync成功后，在开发容器的 `/workspaces/RMCS` 执行：

```bash
.script/identification/remote-wheel-leg-identify start
```

这个入口会校验远端配置和控制库哈希，切换到成对辨识图，并创建独立的MCAP录包进程。保持双下，确认 `rosbag2_recorder` 已订阅 `/wheel_leg/identification/sample` 后，再拨双中开始动作和发布辨识样本。当前启动脚本会确认 rosbag2 实际订阅和未暂停服务，保存 `recording-ready.json` 后才打印可双中提示。

普通 `.script/attach-remote -r` 或 `rmcs-cli` 的 `r` 会使用远端 `env_setup.bash` 中的默认机器人类型。2026-09-28排查时该默认值仍是 `wheel-leg-infantry-rl`；它没有成对辨识轨迹控制器，且 `calibration_ready: false`，所以即使收到双中也不会执行本次辨识。不要通过打开RL标定开关来处理这个启动入口错误。

本次随后已通过远端 `set-robot wheel-leg-infantry-pair-identification` 同时修改 `/root/env_setup.bash` 和 `/root/env_setup.zsh`，使普通重启也进入辨识图。原文件保存在远端 `/root/identification_bags/startup-profile-before-pair-20260927T231945Z/`。退出本次辨识用途时再显式选择相应的运行配置；build/sync本身不选择机器人类型，也不会自动新建录包。

实验结束先双下，再执行 `.script/identification/remote-wheel-leg-identify stop` 完成录包；此命令只停止录包，控制器仍在运行。

## 操作与状态

- **新鲜双中**：直接开始使能流程，不要求预先双下停留。首次反馈尚未到达时零力矩等待，最多3s；反馈及机构检查通过后请求清错/使能。收到所选侧启用反馈并通过轨迹预检后才执行动作。
- **新鲜双下**：优先释放六轴主动指令、清零积分和轨迹状态，撤销使能/清错请求，并复位时钟基准。内部指令采用项目的NaN释放标记，驱动将其转换为零力矩MIT；NaN不会作为数值下发。即使电机反馈过期、发生故障或执行时钟跳拍，也能走到这条复位路径。
- **硬件失能**：轮电流为零；四个关节的FD优先排队，然后在同一发送批次追加 `Kp=Kd=0, t_ff=0` 的MIT帧，包含未选侧。保留系统帧优先顺序，避免零帧挤掉失能指令。这里证明主机排队行为，实机失能仍以反馈为准。
- **故障/动作完成**：保持双中不会自动重跑。双下复位后再次双中；重新使能仍需满足反馈、对侧失能、限位等条件。
- **遥控过期或运行中离开双中**：撤销请求、输出零并锁定故障；过期的“双下”不能清除故障锁。两个拨杆从双下先后拨到双中可以正常起动。

双下失能后腿部仍受自身重力和气簧作用；“零力矩”指主动电机指令，不表示悬空机构不会被动运动。本轮没有启动硬件。

## 参数来源与单位

来源：[feat/rmcs_rl，fdb5573a9894537c296cafffc65ac80a1c54eb89](https://github.com/Alliance-Algorithm/RMCS/blob/fdb5573a9894537c296cafffc65ac80a1c54eb89/rmcs_ws/src/rmcs_bringup/config/wheel-leg-infantry-rl.yaml)。采用代码实际数值；上游注释中的Kp=20与配置Kp=10不一致，以10为准。

|项目|本轮值|含义|
|---|---|---|
|模型offset，LH/LK/RH/RK|`[-1.6,-2.93,1.6,2.93]` rad|先加offset再相位折返/连续解缠|
|模型sign|均+1|四轴硬件已reversed，不重复反号|
|MIT编码P/V/T范围|12.5rad / 45rad/s / 54Nm|与驱动寄存器一致；不代表允许输出54Nm|
|MIT帧p/v/Kp/Kd|均0|只发送力矩前馈|
|PC位置Kp|6|输出速度目标，另加参考速度|
|PC速度Kp/Ki/Kd|10 / 50 / 0|Ki使用秒制积分；上游为每1ms拍.05|
|积分状态限|±.4|积分项上限±20Nm；有条件抗饱和|
|控制器/硬件力矩限|±20Nm|用户本轮授权上限；上游运行配置为±40Nm|
|速度/参考加速度限|.6rad/s / .8rad/s²|保留慢速辨识设置|

上游积分累计误差限±400，乘.05形成±20Nm；当前累计 `error*dt`，因此转换为±.4和Ki=50。200Hz控制周期、积分更新顺序和抗饱和实现不同，必须在MuJoCo中复现本轮实现，不能只复现上游参数。输出限幅是软件指令限幅；MIT离散编码存在约.0264Nm每格的量化，反馈力矩也不是独立力传感器测量。

## 同步出现 Sys_blocked_io 时

2026-09-28在本机Unison 2.53.8上，通过非阻塞输出管道积压复现了同名异常及 `Uitext.Body.alwaysDisplay` 调用栈。`props`/`file`行本身是同步列表，不能当作失败项或完成证明。原包装脚本另有子进程失败退出码未透传、完成标记依赖读取分块的问题。

`.script/sync-remote`现使用独立读写偏移的临时普通文件承接Unison日志，隔离终端背压；按完整行识别完成，跳过/失败项不能放行；子进程失败向调用者返回非零，并关闭等待连接。10项离线测试通过，包含非阻塞日志突发、日志任意分块、失败不放行，以及真实Unison同步600个文件及后续watch更新。没有将此测试连接到机器人。

若只是遇到该同步异常且上次build已成功，无需重新build。在开发容器项目根目录重启 `.script/sync-remote`（只保留一个实例），另一终端运行 `.script/wait-sync`；成功返回后再使用辨识专用start入口。不要以同步列表已经滚动很多行为由跳过完成检查。

## 双中后的实际停机与时间戳竞争

远端 `left-pair-20260927T231612Z` 录包显示，左髋和左膝收到使能后均报告status=1，约0.808s后进入phase=2。前两次尝试因遥控状态变化而以reason=3退出；第三次在phase=2开始约0.239s后以reason=80锁停，尚未完成初始0.7s保持段，因此观察不到轨迹位移。

reason=80那一拍，六轴反馈年龄约为 `[0.666,0.666,3.589,3.589,0.175,1.070]` ms，IMU约0.290ms，但聚合 `feedback_fresh=false`。硬件的新鲜度函数先读取当前时间，再读取回调更新的原子时间戳；回调插入两者之间时，新收到的帧会被误认为来自未来。代码改为先取得时间戳快照，再读比较时钟，覆盖聚合、DM、单侧DM和DR16检查。保留电机/IMU 50ms、DR16 100ms阈值及缺失/真实未来时间戳拒绝规则。

新增确定性回归测试在读时钟时注入一次回调更新，复现原先的先时钟后时间戳顺序会误判；另检查缺失、过期边界及快照中真实未来时间戳仍被拒绝。该竞争窗口由代码和测试确认，实机连续运动是否还有其他停机原因仍须后续轨迹验证。

上述录包中途混入了重新启动的RL图（tick回退、控制器字段缺失），只用于故障诊断，不能作为参数拟合数据。`left-pair-20260927T231958Z` 在保持双下期间关闭，样本数为0，也不用于拟合。

## PROBE运行时软阈值统一为诊断

随后封存 `left-pair-20260927T235604Z/bag`，共21934条样本、21.933s（含使能预检）。本次主轨迹实际运行21.125s，完成至segment 13；左髋编码器总摆幅5.595°，左膝7.694°，右侧基本不动。髋指令力矩范围约[-18.954,0.104]Nm，膝约[-0.690,19.957]Nm，停机并非20Nm限幅触发。

reason=106对应 `PairFault::kStoppingDistance`。终端相对主动轴位置为-1.282316rad、相对速度-0.329670rad/s，距下侧软件边界0.132684rad；未辨识的制动假设0.4rad/s²算出刹停距离0.135853rad，因3.17mrad差额硬停。当时没有越过配置的几何边界。

依据用户减少保护的要求，PROBE现将运行时速度/估算刹停距离、位置/速度跟踪误差、未驱动侧被动速度、起点向外小幅漂移及未达到预设开腿进度统一作为诊断警告。加速度仍为诊断。每类警告限次输出，完整q/dq/力矩仍由sample记录。

实际几何范围检查先独立执行，避免先返回速度/刹停估计而掩盖真实越界；数值有效性、反馈有效性、驱动故障/所选侧权限、双下优先失能和20Nm力矩上限保持。轨迹目标的预检与速度/加速度设计边界不变。HOLD/TRAJECTORY的跟踪与运动范围检查不跟随PROBE放宽，后续正式轨迹仍需测量标定。

新增回归覆盖：估算刹停不足允许PROBE继续，实际相对轴越界仍失能；同时超过速度、跟踪误差及被动侧速度阈值仍可在几何范围内运行，双下在反馈缺失时仍优先释放全部轴。规划层测试还覆盖几何越界不能被大速度掩盖及非有限数据仍拒绝。
